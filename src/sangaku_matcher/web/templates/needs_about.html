{# ── Overview ── #}
概要

sangaku-matcherの need_fit スコアラーは、企業の推定技術ニーズと入力シーズの意味的類似度を算出します。推定ニーズは「ニーズテキスト」と「ニーズベクトル（384次元）」のペアで構成され、以下のプロセスで生成されています。

現行バージョン: v1（テンプレートベース） 対象: {{ company_count }}社 カバレッジ: 100% ベクトル: multilingual-e5-small (384d)
{# ── Generation Logic ── #}
生成ロジック（v1）

各企業のニーズテキストは、3つの要素を組み合わせて自動生成されます。

1. 業種テンプレート

主要業種ごとに、その業種に典型的な技術ニーズのキーワードリストを定義しています。業種が一致する企業には同一のキーワード群が割り当てられます。

2. R&D特性修飾

R&D投資比率（rd_intensity）に応じて3段階の文脈テキストを付与します。

R&D比率修飾テキスト
> 5%先端技術の外部導入に積極的
> 2%技術課題の解決パートナーを求めている
その他外部技術による事業革新を模索している
3. 規模修飾

売上高に応じて連携の受入体制に関する文脈を付与します。

売上高修飾テキスト
> 1兆円大手企業として、大規模な共同研究や技術ライセンスの受入体制がある
> 1000億円中堅〜大手として、特定領域の技術パートナーシップを重視
その他成長企業として、大学発技術のスピーディーな事業化に関心
4. ベクトル化

生成されたテキストを intfloat/multilingual-e5-small（384次元多言語モデル）でエンコードし、needs_vector として保存します。マッチング時にはこのベクトルと入力シーズのベクトルのコサイン類似度が need_fit スコアとなります。

{企業名}の推定技術ニーズ。{R&D特性修飾}。{規模修飾}。求める技術領域: {業種テンプレート}

{# ── Limitations & Roadmap ── #}
制約と改善ロードマップ
現行版（v1）の制約
  • 業種単位のテンプレート: 同一業種内の企業は同じニーズキーワードを持ち、個社ごとの差別化がされていない
  • R&D実態の未反映: 有価証券報告書の研究開発活動セクションのテキストは未活用
  • 中期計画の未反映: 中期経営計画テキスト（新規事業領域への言及）は未取得
v2: EDINET + LLM推定（計画中）

EDINET API v2から有報の「経営方針、経営環境及び対処すべき課題等」セクションを取得し、Claude APIで新規事業領域・求める技術領域・投資予算規模を構造化抽出。個社別のニーズテキストを生成する。

v3: マルチソース統合（将来構想）

特許出願パターン分析（Google Patents BigQuery）、産学連携ニュース・プレスリリース解析、マッチング結果へのユーザーフィードバック学習を統合し、リアルタイムのニーズ変化を検出する。

{# ── Scoring Integration ── #}
マッチングスコアへの組み込み

推定ニーズデータは、五層価値モデルの 第1層：技術的価値（need_fit）として、重み0.20で総合スコアに反映されます。

スコアラー層重み算出方法
tech_proxL1 技術0.25R&Dベクトルとの逆U字類似度
need_fitL1 技術0.20ニーズベクトルとの線形類似度
abs_capL3 知識0.20R&D投資 + 認知的近接性
open_innoL5 生態系0.15OI成熟度 + 連携幅 + ハブ度
past_tiesL2 関係0.10連携量 + 多様性 + 最新度
future_optionL4 将来0.10R&D幅 + 探索距離 + 柔軟性
